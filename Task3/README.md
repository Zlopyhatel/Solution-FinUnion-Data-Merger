# Задание 3. Целевая архитектура данных и аналитическая платформа (To-Be, 12 месяцев)

## 1. Описание содержимого папки
Данный каталог содержит архитектурные спецификации целевого ландшафта платформы данных объединенного банка по результатам полной таргетной централизации и вывода из эксплуатации ИТ-систем RetailBank. 

## 2. Структура документов
*   `target-data-architecture.md` — Компонентное описание целевого ландшафта To-Be с разделением операционной (OLTP) и аналитической (OLAP) нагрузки, а также спецификация ролей онлайн-MDM, Apache Kafka и Apache Airflow.
*   `architecture-options.md` — Сравнительный анализ глобальных подходов (PostgreSQL, Data Lakehouse, Data Mesh) и обоснование выбора гибридной архитектуры для FinUnion.
*   `analytical-model.md` — Проектирование аналитической витрины для домена «Анализ транзакций» по денормализованной схеме «Звезда» (таблица фактов и плоские измерения) с обоснованием структуры суррогатных ключей дат и филиальной иерархии.
*   `data-products.md` — Спецификация доменных продуктов данных (Data Products) в рамках методологии Data Mesh, распределенных по реальным бизнес-департаментам банка и сопоставленных с сервисными доменами референсной модели BIAN.
*   `dwh-lakehouse.md` — Детальный регламент взаимодействия и разделения объемов данных между реляционным DWH и распределенным объектным хранилищем на базе S3, Apache Iceberg и Trino, включая анализ инфраструктурных ограничений и сетевых штормов.

## 3. Ключевые архитектурные принципы To-Be
*   **Разделение стоимости и точности (Гибрид):** Хранение высокоточных балансов Главной книги для ЦБ РФ в классическом реляционном DWH на быстрых дисках. Вынос 98% объема данных (петабайты логов кликстрима, архивов и транзакций) в экономичный колоночный формат Parquet/Iceberg на дешевом S3.
*   **Онлайн-защита от мусора:** Перевод MDM Customer Hub из ночного батча в онлайн-режим работы через API-запросы из CRM во фронт-офисе для предотвращения генерации дубликатов на этапе ввода паспорта.
*   **Оптимизация вычислений:** Применение распределенного движка Trino для выполнения параллельных и федеративных SQL-запросов с использованием механизмов Pushdown Predicates для минимизации межсерверного сетевого трафика.
