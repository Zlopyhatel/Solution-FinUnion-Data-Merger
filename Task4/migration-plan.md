# Инкрементальный план миграции данных (Migration Plan)

В данном документе представлен пошаговый инкрементальный план переноса данных из систем-источников RetailBank в целевую аналитическую и операционную платформу FinUnion. План рассчитан на 12 месяцев.

## 1. Таблица этапов миграции данных

| Этап | Содержание этапа | Результат этапа (Deliverable) |
| :--- | :--- | :--- |
| **1. Data discovery** | Инвентаризация ИТ-систем поглощаемого банка, аудит таблиц, структуры полей, описание существующих потоков и закрепление владельцев данных (Data Owners) [1.1]. | Утвержденный сквозной реестр данных и ИТ-ландшафта As-Is [1.1]. |
| **2. Data Mapping & Cleansing** | Анализ качества данных. Разработка правил перевода форматов (маппинга) из legacy-справочников в каноническую модель FinUnion (например, трансляция архивных тарифов, масок счетов, кодов полов, ФИАС-адресов) [1.1]. | Спецификация правил трансформации данных и готовые интеграционные скрипты Airflow/dbt [1.1]. |
| **3. Customer Data MDM Ingestion** | Первоочередная миграция анкетных данных клиентов (ФЛ/ЮЛ) и сотрудников в центральный `MDM Customer Hub` для проведения нечеткого поиска, дедупликации и присвоения сквозного UniqueID [1.1]. | Очищенный мастер-справочник контрагентов с UniqueID, загруженный на детальный слой DWH [1.1]. Обеспечена ссылочная целостность (Foreign Key) для продуктовых слоев. |
| **4. Test Migration Sprint & Extraction** | Запуск тестовых миграционных пайплайнов на изолированных тестовых средах (прогон 5-10% случайных выборок счетов и кредитов). Контроль объемов, подсчет строк и проверка хэш-сумм батчей на входе и выходе. | Верифицированные интеграционные пайплайны. Устранение технических дефектов (обрезание строк, потеря копеек) до финального переноса. |
| **5. Full Active Portfolio Migration** | Полное копирование активного портфеля (открытые счета, действующие кредиты, балансы) в операционный контур и сырой слой хранилища. Тотальный форматно-логический контроль (ФЛК) и сверка балансов (Data Reconciliation) [1.1]. | Консолидированная база данных. Финансовая сверка остатков между старой АБС и целевой системой FinUnion копейка в копейку. |
| **6. Analytical Validation & Marts Go-Live** | Сборка финальных доменных продуктов данных (витрин Розничного бизнеса, МСБ, Рисков) на базе **Data Lakehouse (S3/Iceberg)** [1.1]. Проверка отчетов в BI на наличие скрытых нестыковок и логических аномалий за прошлые периоды. | Полноценный запуск целевой аналитической платформы To-Be. Бизнес-пользователи и регулятор работают на чистых объединенных данных [1.1]. Старые legacy-хранилища официально выводятся из эксплуатации. |
