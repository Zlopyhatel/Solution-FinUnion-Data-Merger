# Задание 2. Промежуточная архитектура данных (MVP, 3 месяца)

## 1. Описание содержимого папки
Данный каталог содержит проектную документацию для организации интеграционного контура объединенного банка на этапе промежуточного состояния (горизонт 3 месяца). Решения сфокусированы на оперативной консолидации клиентской базы, разграничении зон ответственности систем и построении первой управленческой отчетности.

## 2. Структура документов
*   `master-systems.md` — В документе определены мастер-системы для ключевых бизнес-сущностей в промежуточном (3 месяца) и целевом (12 месяцев) состояниях. Логика распределения опирается на принцип таргетной централизации ИТ-ландшафта и референсные границы сервисных доменов BIAN.
*   `data-ownership.md` — Регламент владения данными, закрепление бизнес-ролей (Data Owners) и стюардов данных (Data Stewards) за критическими информационными объектами для контроля качества.
*   `data-flows.md` — Технический реестр потоков данных (Data Flows) между операционными системами, модулем дедупликации и аналитическим хранилищем на основе контекстной диаграммы DFD Уровня 0.
*   `data-flow-management.md` — Эксплуатационный регламент управления потоками, включающий требования к SLA, правила информационной безопасности, маскирование ПДн, форматы передачи и методы мониторинга.
*   `data-dependencies.md` — Матрица технологических рисков интеграционного контура на уровне данных с описанием прямых последствий для бизнес-процессов (выход за рамки ночного окна, эффект "Monster Records" и сбои каскадного расписания).

## 3. Ключевые архитектурные принципы MVP
*   **Изоляция инфраструктуры:** Применение технологии CDC (Debezium) для выгрузки транзакционных логов из legacy-АБС RetailBank для защиты слабой аппаратной части поглощаемого банка от падения при тяжелых ночных запросах.
*   **Контроль целостности:** Использование асинхронного пакетного оркестратора Apache Airflow для каскадного запуска пайплайнов и ночной сверки контрольных хэш-сумм и количества строк (Data Reconciliation).
*   **Централизованная дедупликация:** Вынос процесса склейки кросс-банковских дубликатов в выделенный ночной batch-модуль MDM Customer Hub до момента загрузки данных в детальный слой DWH для обеспечения чистоты метрик.
