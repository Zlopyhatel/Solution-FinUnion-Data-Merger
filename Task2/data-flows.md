# Описание основных потоков данных переходного периода (MVP, 3 месяца)

В данном документе приведена детальная техническая спецификация потоков данных (Data Flows) для промежуточного состояния ИТ-ландшафта. Реестр составлен на основе контекстной диаграммы DFD Уровня 0.

---

## 1. Реестр интеграционных и аналитических потоков данных

| № | Поток данных (Источник ➔ Приёмник) | Передаваемые сущности | Тип действия с данными | Режим обмена | Краткое обоснование потока |
| :- | :--- | :--- | :--- | :--- | :--- |
| **1** | **CRM FinUnion** ➔ **Integration Layer (Airflow)** | Клиент ФЛ, Клиент ЮЛ, Сотрудник банка, Обращение клиента. | **Read** (чтение дневных изменений) | Асинхронный, **Daily Batch** (ночное окно, 01:00) | Извлечение сырых анкетных данных и истории обращений клиентов FinUnion без создания онлайн-нагрузки на CRM в рабочее время. |
| **2** | **CRM RetailBank** ➔ **Integration Layer (Airflow)** | Клиент ФЛ, Клиент ЮЛ, Сотрудник банка, Обращение клиента. | **Read** (чтение изменений логов) | Асинхронный, **CDC** (Debezium фоном в течение дня) + ночной **Batch** | Сбор анкетных данных интегрируемого банка. CDC применяется для минимизации транзакционной нагрузки на legacy-инфраструктуру. |
| **3** | **Продуктовые системы FinUnion (Core, Loans, Cards)** ➔ **Integration Layer** | Договор, Счёт, Карта, Платёж, Транзакция, Тариф, Отделения. | **Read** (извлечение срезов остатков и транзакций) | Асинхронный, **Daily/Hourly Batch** (карты — раз в час, счета — ночью) | Систематический сбор информации по открытым продуктам, балансам и проводкам FinUnion для последующего аналитического сопоставления. |
| **4** | **Продуктовые системы RetailBank (Core, Loans, Cards)** ➔ **Integration Layer** | Договор, Счёт, Карта, Платёж, Транзакция, Тариф, Отделения. | **Read** | Асинхронный, **CDC** (для транзакций и счетов) + ночной **Batch** (для тарифов) | Поставка финансовых и продуктовых данных интегрируемого банка. Защищает АБС от падения и блокировок таблиц при тяжелых выгрузках. |
| **5** | **Integration Layer (Airflow)** ➔ **MDM Customer Hub** | Клиент ФЛ, Клиент ЮЛ. | **Validate, Read, Enrich, Create, Update** | Асинхронный, **Batch** (запуск ночью после сбора всех CRM-выгрузок) | Центральное ядро MVP. MDM-модуль выполняет ФЛК (проверку ИНН/СНИЛС), склеивает дубли по правилам нечеткого поиска и генерирует сквозной **UniqueID**. |
| **6** | **MDM Customer Hub** ➔ **DWH (Staging Area)** | Реестр участников (Party Data Management) с привязанными UniqueID. | **Create, Update** (запись мастер-реестра в аналитический слой) | Асинхронный, **Batch** (по завершении ночной работы алгоритмов MDM) | Поставка очищенного эталонного справочника контрагентов в DWH для обеспечения возможности сквозной кросс-банковской аналитики. |
| **7** | **Integration Layer (Airflow)** ➔ **DWH (Staging Area)** | Договор, Счёт, Карта, Платёж, Транзакция, Тариф, Отделения, Обращения. | **Create** (историческая дозапись), **Validate** (ФЛК-контроль качества) | Асинхронный, **Batch** (ночная загрузка продуктовых блоков) | Наполнение сырого слоя DWH транзакционными данными. На входе работает щит **Great Expectations**, отсекающий битые строки в карантин. |
| **8** | **DWH (Слой витрин / Data Marts)** ➔ **BI (Система отчетности)** | Консолидированные аналитические витрины Розничного бизнеса, МСБ и Рисков. | **Read** (чтение готовых витрин), **Aggregate** (микро-группировки на стороне BI) | Синхронный/Асинхронный, **Batch** (обновление витрин раз в сутки утром) | Обеспечение руководства и бизнес-аналитиков объединенного банка управленческой отчетностью по динамике и эффективности слияния. |
| **9** | **DWH (Слой Главной книги)** ➔ **Регулятор (Внешняя выгрузка)** | Регуляторные балансовые отчеты, отчеты по просрочке и резервам. | **Read, Aggregate** (формирование итоговых агрегатов для ЦБ) | Асинхронный, **Batch** (выгрузка строго по регламентному графику ЦБ РФ) | Выполнение обязательных законодательных требований перед Банком России по предоставлению финансовой отчетности Главной книги. |
| **10** | **Компоненты платформы (DWH, MDM, IL)** ➔ **DataHub** | Метаданные (схемы таблиц, логи dbt, структуры пайплайнов Airflow). | **Read** (пассивный сбор структуры метаданных) | Асинхронный, **Batch** (периодическое фоновое сканирование) | Обеспечение сквозной трассируемости происхождения данных (**Data Lineage**). Позволяет инженерам видеть путь любого поля от BI до legacy-АБС. |
