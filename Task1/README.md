# 📂 Task 1. Анализ данных, сущностей и хранилищ

## 🎯 Цель модуля
Проектирование целевого фундамента данных для объединенной финансовой группы FinUnion после поглощения регионального банка RetailBank. 

В рамках данного этапа выполнен детальный анализ систем As-Is, осуществлено их разделение на логические слои, сформированы требования по защите операционного контура от перегрузки и выполнено приведение сущностей к международному банковскому стандарту.

---

## 🛠️ Результаты этапа (Что сделано):

### 1. 📊 Комплексный анализ бизнес-сущностей (`entities.md`)
* Выделено **12 ключевых сущностей** данных (вместо стартовых 10).
* Добавлены критичные для сквозной аналитики блоки (*Сотрудники* и *Обращения клиентов*).
* Зафиксированы потенциальные дефекты качества данных (дубли, расхождения форматов, пропуски ИНН), возникающие **в обеих исходных системах**, а не только в legacy-базе интегрируемого банка.

### 2. 🗺️ Логическая модель данных (`logical-data-model.md`)
* Спроектирована каноническая ER-диаграмма в Draw.io.
* Заложен сквозной идентификатор **UniqueID** на базе центрального модуля **Party Data Management (PDM)** для формирования единого профиля клиента.
* Выстроена целевая реляционная цепочка финансовых операций: 
  `Договор` ➔ `Счёт` (с гео-привязкой к Отделению) ➔ `Платёж` (бизнес-действие клиента) ➔ `Транзакция` (бухгалтерская проводка в АБС).

### 3. 🛡️ Классификация данных и ИБ (`data-classification.md`)
* Осуществлено распределение сущностей по уровням безопасности и требованиям 152-ФЗ.
* Определен **Критический (High)** уровень важности для остатков на счетах и проводок (Банковская тайна).
* Установлен **Высокий** уровень критичности для паспортов (ПДн) и текстов обращений в CRM.
* Назначены целевые средства защиты: маскирование, шифрование таблиц (TDE) и ролевой доступ (RBAC).

### 4. 🗄️ Стратегия целевых хранилищ (`storage-strategy.md`)
* Реализовано жесткое разделение операционной (OLTP) и аналитической (OLAP) нагрузок.
* Поведенческий BI (миллиарды записей о платежах) перенесен в экономичное объектное хранилище **Data Lakehouse (S3 + Iceberg)**.
* Бухгалтерские проводки для регуляторной отчетности закреплены за классическим **DWH**.
* Тексты обращений изолированы в **Поисковый движок** для обеспечения мгновенного полнотекстового поиска.

### 🗺️ Маппинг на стандарт BIAN (`reference-model.md`)
* Подготовлена таблица перевода физических таблиц на «общий язык» индустрии (например, `Current Account`, `Payment Execution`).
* Сформировано архитектурное обоснование, как фреймворк BIAN позволит в будущем осуществить переход к распределенной доменной архитектуре **Data Mesh**.
